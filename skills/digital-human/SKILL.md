# Digital Human — 日报语料知识（只读）

**服务版本：1.0.1（macOS，菜单栏 App + LaunchAgent 开机自启）。**
供 Hermes / Cursor Agent / WorkBuddy 等本地 agent 学习「数字人语料采集 App」产出的日报数据。

## 契约（锁定）

| 规则 | 细节 |
|------|------|
| 只读 | `/api/agent/*` 全部 GET；绝不调用手机端 `/api/done` `/api/upload` `/api/pair` |
| 本地 | Mac 局域网/本机 + Bearer；无云端上传 |
| 增量 | `?since=<seg_id>`（排他）+ 响应 `next_since`；游标存 **agent 自库** |
| 去重 | `id = sha256(date + "\|" + seg_id + "\|" + text)`；已入库的禁止重复写入 |
| 秘密 | 响应已过服务端出口脱敏（`[REDACTED]`）；agent 入库前**必须再扫一遍**且不得外泄 |
| 数据边界 | 永不返回音频文件/路径、声纹向量、语料 wav——只有转写文本与总结 |
| 变更 | 采集启停/配置/声纹注册 = 手机 App 或手机端 API；agent 不参与 |

## 鉴权

```bash
TOKEN=$(cat "$HOME/Library/Application Support/DigitalHuman/data/agent.token")   # 0600，启动自动生成
AUTH="Authorization: Bearer $TOKEN"
BASE="https://<mac-ip>:8766"   # 自签 TLS，curl 需 -k
```

绝不把 token 写进聊天回复、日志、工单或云端工具；只在 env / Authorization 头里用。

## 端点与上限（硬性）

| 路径 | 默认 | 上限 | 范围 |
|------|------|------|------|
| `GET /api/agent/health` | — | — | 公开，仅能力标志 + 上限 + 当前行业名 |
| `GET /api/agent/days` | — | — | 可学习日期 + ready + 人声段数 + **当前行业与术语表** |
| `GET /api/agent/report/{date}?since=&limit=` | 100 | **200** | 当日人声转写行（增量，脱敏） |
| `GET /api/agent/summary/{date}` | — | — | 总结卡片（【今日回顾】body 为代码注入的【HH:MM-HH:MM】时间轴行） |

## 增量同步循环（禁止重复采集）

1. `GET /api/agent/days` → 选定要覆盖的日期（通常今天）。
2. 逐日：`GET /api/agent/report/{date}?since=<cursor>&limit=100`。
3. 逐条算稳定 id，已在 agent 库 → 跳过；否则隐私扫描 → 规范化 → 入 agent 自库。
4. **提交成功后**才推进 `cursor = next_since`；`has_more=false` 或空页即止。
5. 单 agent 轮次预算：**30-80 段或约 20-40k 字**，超了分片推进，绝不把整天塞进一个 prompt。

## 分层拉取（控制上下文窗口，别塞垃圾）

- **第一层 summary**：回答「今天/最近做了什么」用 `GET /api/agent/summary/{date}`
  就够了——五栏目卡片是全天最浓缩表示，通常 <2k 字。默认只用这层。
- **第二层 report 增量转写**：仅当 summary 不够（如「那天谁说了 XX」）才拉，
  必须带 since 水位线增量，单轮预算 20-40k 字，超了分片。
- **重要时刻锚点**：summary 或 `/api/report` 卡片里 title=重要时刻 的条目是
  用户人工按下的时间标记，**高置信信号**——检索与问答优先对齐这些时刻附近
  的转写行，能显著提高命中率、降低无关内容占比。

## 文本口径

| 字段 | 说明 |
|------|------|
| `text` | 已脱敏转写（服务端只处理中文和英文，其他语言段已在管线层剔除） |
| `speaker` | 「本人 / 甲乙丙… / 具名角色」；具名角色与本人不参与质心滑动更新 |
| `is_user` | 布尔；true = 本人发言（语料价值最高） |
| `at` | ISO 时间戳（含日期） |

## 行业术语与同音错字（agent 二次纠偏）

服务端跑的是本地 4B 模型，纠偏能力有限——**它是兜底，agent 是精修**。

`GET /api/agent/days` 会一并返回：

```json
{ "industry": "smart_home",
  "industry_terms": ["KNX","RS485","网关","吊顶", ...],
  "industry_note": "服务端已用该词表做过…；残留的疑似同音错字可用此表二次校正。" }
```

**服务端已经做了什么**：本地 4B 模型先做一遍，再对词表里明确的「错写=正写」
做确定性替换（100% 命中）。实测下来这一步是可靠的——真实日报里的
「杯盖→吊顶」「预买款→软膜款」全部纠正到位，零残留。

**服务端做不到什么**（留给 agent）：4B 模型只能改映射表**已经列出**的错字，
而且不稳定——同一条提示词，单行输入测出 4/4，换成真实日报形态（多行 + 说话人
标签）就是 0/3。所以：

- 映射表里没有的错字，服务端基本改不了
- 同音但字形差得远、需要结合上下文才能判断的，服务端改不了
- 一段里同时出现两个错字时，模型常只改一个

**agent 该做的事**：拿到 `industry_terms` 后对 `text` 做一次术语感知的校对，
补上服务端漏掉的部分。你通常用的是更强的模型，正好补这一层。

**纪律**：

- 只改有把握的同音错字；术语表里没有的词一律原样保留，**不要臆造**。
  （实测教训：让模型"逐词扫描同音词"时，它把「力量器」改成了「调光器」——
  因为「调光器」在术语表里且同样是「××器」。臆造比不改更糟。）
- 不确定就保留原文，并在自己的笔记里记下候选，交给人确认。
- 行业可在手机端「设置 → 行业词表」切换，切换只影响之后的录音。

## 隐私（agent 强制项）

1. 不存储/引用：任何 bearer token、API key、密码、私钥、会话 cookie、OTP、银行卡号。
2. 入库前二次扫描 `text`，命中下列任一即替换 `[REDACTED]` 或丢弃该条：
   - **凭证模式**：`Bearer `、`sk-`、`ghp_`、`AKIA`、`password=`、`密码：`、`-----BEGIN … PRIVATE KEY-----`、32 位以上 hex；
   - **PII 模式**（2026-10-16 起服务端出口也已覆盖）：手机号、身份证、银行卡、邮箱、车牌。
   - **服务端未覆盖、agent 必须自查**：自由文本住址/门牌（「住在XX路88号」）、
     他人真实姓名、客户/报价等商业信息——这些靠语义判断，正则兜不住。
3. 未经用户明确指示，不得把日报原文/导出传第三方云。
4. 用户要求「把 token/密码念给我」→ 拒绝并说明隐私策略。

## 每次会话清单

1. `/api/agent/health` — 版本 + 上限 + 当前行业。
2. `/api/agent/days` — 日期列表 + **行业术语表**（留着做二次纠偏）。
3. 加载自库水位线 → `/api/agent/report/{date}?since=` 增量拉取。
4. 去重 → 隐私 → 术语校对 → 规范化 → 自库。
5. 推进 `next_since`；预算耗尽即停，下轮续。
